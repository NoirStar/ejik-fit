# 커리어 분석 v2 경계

## 목적

홈, 커리어맵, 추천 채용공고는 웹의 `buildCareerAnalysis`가 만든 동일한 결과를
표시한다. 화면 컴포넌트는 방향을 다시 분류하거나 별도 점수를 만들지 않는다.
현재 분석 버전은 `career-evidence-v2.0`이며, 프로필·보유 기술·공고 ID와 마지막
확인 시각으로 결정적인 스냅샷 ID를 만든다.

## 사용하는 근거

- 프로필: 현재·과거 직무, 주요 업무, 프로젝트·성과, 산업, 업무 유형, 경력 기간과
  수준, 기술 사용 기간과 최근성, 관심·제외 분야, 희망 근무지와 고용 형태
- 채용공고: 제목, 목록 응답의 `description_excerpt`, 필수·우대·구분 없는 기술,
  경력 조건, 근무지, 고용 형태
- 추천 자격: 공고에서 역할 또는 주요 업무가 명시적으로 확인되고, 프로필의 직무·
  업무·프로젝트·산업 근거와 추가 근거가 함께 있을 때만 부여한다. 기술 한 개 또는
  역할 제목만으로는 추천하지 않는다.
- 대표 공고: 해당 방향으로 분류되고 위 추천 자격을 충족하는 공고만 선택한다.

백분율 적합도나 합격 가능성은 계산하지 않는다. 프로필에 없는 정보는 부족하다고
판정하지 않고 `현재 프로필에서 확인되지 않음`으로 표시한다.

## 분야와 시장 집계

분야 분류는 공고 제목·업무 문장과 분야별로 관리하는 명시적 기술 조합을 사용한다.
기술 관계 그래프의 동시 출현만으로 분야나 커리어 이동 경로를 만들지 않는다.
기업 수는 `company_slug`를 우선하고, 없으면 정규화한 기업 표시명을 사용해 한 번만
센다. 공고 수와 기업 수는 항상 별도로 표시한다.

분야 시장은 공고 목록이 정상인 경우에만 집계한다. 그래프 요청이 실패해도 분야
공고 집계는 유지하고 기술 관계만 일부 실패로 표시한다. 공고 요청 실패는 0건으로
바꾸지 않는다. 기술 그래프 API의 `limit` 계약은 웹과 API 모두 최대 60이다.

## 데이터 범위와 호환성

분석은 커리어핏이 수집해 마지막으로 확인한 공개 공식 채용공고 표본만 사용하며
대한민국 전체 채용시장을 대표하지 않는다. 과거 스냅샷이 충분하지 않으면 증가·감소
추세를 만들지 않는다.

브라우저 데이터는 `careerfit:*`를 우선한다. 새 값이 없을 때만 유효한
`ejik-fit:*` 값을 새 키에 쓴 뒤 재확인하며, 호환 기간 동안 기존 키를 삭제하지
않는다. 외부 URL, 패키지명, API 경로와 배포 프로젝트 식별자는 이 사용자 노출
브랜드 변경과 분리해 유지한다.
