# 커리어 분석 경계

## 단일 분석 계약

홈, 내 커리어, 커리어 방향 비교와 추천 채용공고는 FastAPI의
`POST /api/career/analyze`가 반환하는 동일한 도메인 결과를 표시한다. 화면은 결과를
다시 분류하거나 별도 점수를 만들지 않는다. 현재 분석 버전은
`career-evidence-v3.0`이다.

요청은 프로필, 보유 기술, 검색 조건과 추천 페이지 조건을 포함한다. 서버는 검색 조건에
해당하는 전체 공개 공고를 먼저 읽고 분석한 다음, 추천 가능한 공고만 정렬·페이지네이션한다.
현재 페이지에 우연히 포함된 공고만으로 추천을 계산하지 않는다.

응답의 `snapshot_id`는 분석 버전, 정규화한 프로필·기술, 공고 ID와 마지막 확인 시각에서
결정적으로 만든다. 웹은 같은 요청 결과를 짧게 캐시하되 다른 스냅샷을 합치지 않는다.

## 사용하는 근거와 제한 조건

- 프로필: 현재·과거 직무, 주요 업무, 프로젝트·성과, 산업, 업무 유형, 경력 기간과
  수준, 기술 사용 기간과 최근성, 관심·제외 분야, 희망 근무지와 고용 형태
- 채용공고: 직무 제목, 업무 설명, 필수·우대·구분되지 않은 기술, 경력 조건,
  근무지와 고용 형태
- 추천 자격: 공고 제목에서 역할이 확인되고, 프로필의 역할·업무·산업·기술 중
  하나 이상의 구체 근거가 함께 있어야 한다.
- 제한 조건: 경력 수준 또는 고용 형태가 명확히 다르면 추천에서 제외한다.
- 대표 공고: 해당 분야로 분류되며 추천 자격을 충족하는 공고만 선택한다.

기술 하나나 일반 표현 하나만 겹치는 결과는 추천하지 않는다. 백분율 적합도와 합격
가능성은 계산하지 않는다. 프로필에 없는 정보는 `현재 프로필에서 확인되지 않음`으로
표시한다.

## 분야 시장 계약

`GET /api/career/market`은 동일한 분야 분류기로 전체 공개 공고 스냅샷을 집계한다.
분야별 공고 수, 중복을 제거한 기업 수, 경력 분포, 근무지, 기술과 최근 공고를 반환한다.
기업은 `company_slug`를 우선하고, 값이 없을 때만 정규화한 표시명을 사용해 센다.

기술 순위는 공고 수와 함께 서로 다른 기업 수를 제공하며 기업 범위를 먼저 정렬한다.
표본이 작은 분야는 `limited`로 표시하고 비교 가능한 통계나 추세처럼 표현하지 않는다.
요청 오류는 0건으로 바꾸지 않는다.

## 기술 추출과 관계

필수·우대 분류는 한국어와 영어 섹션 제목, 문장 안의 required/must/preferred/
nice-to-have 문맥을 사용한다. 기술 관계 그래프는 같은 공고에 함께 등장한 관계만
보여주며 인과관계, 학습 순서 또는 커리어 이동 경로로 사용하지 않는다. 이전
`/api/fit` 계약은 호환성을 위해 유지하지만 핵심 커리어 분석 화면에서는 사용하지 않는다.

## 데이터 범위와 호환성

분석은 커리어핏이 수집해 마지막으로 확인한 공개 공식 채용공고 표본만 사용하며 대한민국
전체 채용시장을 대표하지 않는다. 과거 스냅샷이 충분하지 않으면 증가·감소 추세를 만들지
않는다.

브라우저 데이터는 `careerfit:*`를 우선한다. 새 값이 없을 때만 유효한 `ejik-fit:*`
값을 새 키에 쓴 뒤 재확인하며, 호환 기간 동안 기존 키를 삭제하지 않는다. 외부 URL,
패키지명, API 경로와 배포 프로젝트 식별자는 사용자 노출 브랜드와 분리해 유지한다.
