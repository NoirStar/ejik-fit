# 행동으로 이어지는 옵시디언형 스킬맵 설계

## 목표

스킬맵을 옵시디언 그래프의 외형만 닮은 관계 그림이 아니라, 사용자가 채용 시장의 기술 지형을
안정적으로 훑고 `내 기술과 선택 기술이 시장에서 어떻게 이어지는지`, `어떤 공고를 다음에 볼지`를
결정하는 탐색 도구로 완성한다.

기존 V2의 전체 시장 지도, 선택 주변 보기, 분야 군집, hover 스포트라이트, 선택 분석 레일은
유지한다. 이번 변경은 관계선과 라벨의 과밀을 사용자가 제어하게 하고, 선택 기술을 개인의 보유
기술과 연결해 설명하는 데 집중한다.

## 조사 결과와 제품 해석

옵시디언 공식 그래프의 핵심은 다음과 같다.

- 노트가 노드이고 내부 링크가 선이며, 참조가 많은 노드는 크게 표시된다.
- hover는 해당 노트와 연결만 강조하고, 전체 그래프와 활성 노트 주변의 로컬 그래프를 나눈다.
- Filters, Groups, Display, Forces 설정으로 보이는 범위와 밀도를 조절한다.
- 검색, 확대·이동, 그룹 색, 라벨·노드·선 표시 조절로 복잡한 지도를 단계적으로 읽는다.

그러나 채용 스킬맵에 그대로 복제하지 않는다.

- 공고의 기술 동시 등장은 방향이 없는 관계이므로 화살표는 의미를 왜곡한다.
- 물리력 슬라이더는 사용자가 기술 시장을 이해하는 데 필요한 결정이 아니며 설정 비용만 만든다.
- 생성 시점 타임랩스는 현재 데이터 계약에 신뢰할 수 있는 시계열 의미가 없어 제공하지 않는다.
- 우클릭 메뉴는 모바일 대응과 기존 분석 레일의 행동을 중복한다.
- 관계가 많은 전체 그래프는 필터 없이 쉽게 hairball이 되므로 기본 밀도를 낮춰야 한다.

그래프 시각화 연구의 `search, show context, expand on demand` 원칙과 배치 안정성 결과를 반영한다.
숫자 비교는 그래프보다 목록이 정확하므로 수요·공고 수는 분석 레일에 유지하고, 그래프는 공간적
관계와 경로 탐색에 집중한다.

## 디자인 맥락

- 대상: 채용 시장의 큰 그림을 보고 다음 학습·지원 행동을 정하려는 한국어권 개발자
- 1차 행동: 전체 지도에서 기술 선택
- 2차 행동: 내 기술과 선택 기술의 시장 연결 확인
- 3차 행동: 함께 요구되는 기술 또는 관련 공고 확인
- 톤: 기존 `modern-minimal`, 기술적이고 조용한 데이터 도구
- 구조: `Map / Diagram`의 전체 시장 아틀라스 + 선택 스포트라이트 + 단일 분석 레일
- 보존: 보라색 포인트, Pretendard, 4px 간격, 44px 터치 기준, Canvas 2D 렌더러

## 채택한 방향

### 1. 옵시디언 기능 전체 복제

필터·그룹·표시·물리력·타임랩스를 모두 제공한다. 원본과 닮아 보이지만 채용 탐색에 불필요한
설정이 늘고 저사양 PC와 모바일의 조작 부담이 커져 채택하지 않는다.

### 2. 외관만 더 어둡고 촘촘하게 변경

작은 점, 가는 선, 어두운 배경을 복제한다. 브랜드 일관성과 한글 라벨 가독성을 해치고 사용자의
다음 행동은 달라지지 않아 채택하지 않는다.

### 3. 옵시디언의 탐색 모델을 채용 의사결정에 번역 — 채택

전체 지형과 배치를 유지한 채 평상시 보이는 관계선·라벨만 단계적으로 조절한다. hover와 선택 시
숨겨 둔 주변 관계를 다시 드러내고, 사용자가 요청하면 내 기술에서 선택 기술까지 이어지는 강한
시장 관계를 강조한다. 복잡도는 줄지만 데이터와 force topology는 유지하므로 공간 기억도 보존한다.

## 정보 구조

기존 페이지 뼈대를 유지하고 툴바와 분석 레일만 확장한다.

```text
스킬맵 · 공개 공고 기반 설명 · 데이터 범위
기술 찾기 | 전체/선택 주변 | 내 기술 | 분야 | 보기 설정 | 읽는 법
┌────────────────────────────────────┬──────────────────┐
│ 전체 지도 · 보이는 기술/관계        │ 선택 기술         │
│                                    │ 시장 수요·행동     │
│ 기본은 핵심 관계와 주요 라벨         │ 내 기술과의 연결   │
│ hover/선택 시 주변 관계 복원         │ 다음에 배울 기술   │
│ 경로 보기 시 연결 경로만 강조         │ 함께 요구·관련 공고│
└────────────────────────────────────┴──────────────────┘
```

### 보기 설정

기존 압축 툴바에 `보기 설정` disclosure 하나를 추가한다. 큰 설정 카드나 영구 사이드바는 만들지 않는다.

- 관계선: `핵심`, `균형`, `자세히`
  - 기본 `핵심`은 연결성을 유지하는 최소 backbone과 소수의 강한 보조 관계만 평상시에 표시한다.
  - `균형`은 더 많은 문맥을, `자세히`는 현재 렌더링 예산 안의 모든 관계를 표시한다.
  - 숨긴 관계도 force 계산에는 남기므로 설정 변경으로 노드 배치가 바뀌지 않는다.
  - hover, 선택, 시장 연결 경로에 포함된 관계는 현재 밀도와 무관하게 일시적으로 보인다.
- 기술명: `주요만`, `더 많이`
  - 기본은 분야 대표와 수요 상위 기술 위주다.
  - 더 많이는 라벨 후보 수만 늘리고 충돌 라벨은 계속 생략한다.
  - 라벨 설정도 topology나 카메라를 바꾸지 않는다.

설정에는 `배치는 유지하고 표시 정보만 바뀝니다.`라는 한 줄 설명을 둔다.

## 내 기술과의 시장 연결

선택 기술이 있고 현재 지도에 보이는 내 기술이 하나 이상이면, 표시 중인 관계망에서 선택 기술까지
이어지는 가장 설명력 높은 경로를 계산한다.

- 후보 경로는 최대 4개 관계로 제한한다.
- 비용은 관계 수, 관계 점수, 동시 등장 공고 수를 함께 사용한다.
- 짧은 약한 직결선보다 두세 개의 강한 시장 관계가 더 적절하면 강한 경로를 선택한다.
- 여러 보유 기술 중 총비용이 가장 낮은 기술을 시작점으로 선택한다.
- 동점은 기술명과 관계 ID로 안정적으로 결정한다.

분석 레일에는 다음을 표시한다.

- 제목: `내 기술과의 시장 연결`
- 경로: `C++ → Linux → Docker`처럼 실제 기술명만 표시
- 설명: `공고에서 함께 요구된 강한 관계를 따라 표시합니다. 학습 순서를 뜻하지 않습니다.`
- 행동: `그래프에서 경로 보기` / 활성 상태에서 `경로 강조 끄기`
- 근거: 경로의 관계 수와 가장 약한 구간의 동시 등장 공고 수

내 기술이 없으면 `내 기술을 추가하면 선택 기술까지 이어지는 시장 관계를 볼 수 있습니다.`라고
안내한다. 선택 기술이 이미 내 기술이면 별도 경로 CTA를 만들지 않고 포함 상태를 알린다. 현재 보이는
관계 안에서 경로가 없으면 없는 이유를 짧게 밝히고 전체 지도를 유지한다.

경로 강조는 사용자가 명시적으로 실행할 때만 활성화한다. 활성화하면 경로 노드와 선을 남기고 나머지를
낮은 농도로 처리한다. hover 중에는 hover 문맥을 우선하고, pointer가 빠지면 경로 강조를 복원한다.
기술 선택, 경로 켜기, 보기 설정은 네트워크 요청·simulation 재가열·자동 확대·자동 이동을 일으키지
않는다.

## 데이터 의미와 문구 원칙

- 기술 관계는 `같은 공개 공고에서 함께 요구됨`만 뜻한다.
- 관계 경로는 선수 지식, 학습 난이도, 권장 학습 순서를 뜻하지 않는다.
- `학습 경로` 대신 `시장 연결`을 사용해 인과를 과장하지 않는다.
- `다음에 배울 기술`은 기존 fit API의 공고 근거 추천만 담당한다.
- 노드 크기, 분야색, 내 기술 링, 추천 점, 선 농도의 기존 의미는 바꾸지 않는다.

## 성능과 안정성

- 데스크톱 48개 노드·84개 관계, 모바일 30개 노드·48개 관계 예산을 유지한다.
- 관계 밀도는 Canvas에 전달한 동일 topology의 paint 여부만 바꾼다.
- 경로 계산은 현재 최대 48개 노드·84개 관계에서 메모이즈한 순수 함수로 실행한다.
- 설정 변경과 경로 강조는 Canvas redraw만 요청하고 force simulation은 다시 시작하지 않는다.
- 숨긴 링크는 너비 0과 투명색으로 칠하되 hover/선택/경로 문맥에서는 표시한다.
- 현재 dynamic import, 자동 pause, ResizeObserver rAF 병합, reduced-motion 설정을 유지한다.

## 접근성과 모바일

- `보기 설정`은 native `details/summary`를 사용하고 키보드와 터치에서 동일하게 접근한다.
- 각 설정은 실제 `button`과 `aria-pressed`로 상태를 전달한다.
- 관계선 밀도와 라벨 설정 버튼은 최소 44px이며 라벨은 한 줄로 유지한다.
- 경로는 색뿐 아니라 텍스트 순서와 `경로 강조 중` 상태 문구로도 전달한다.
- 모바일은 기존처럼 페이지 스크롤과 노드 탭이 기본이고, 조작 모드에서만 pan·pinch를 받는다.
- 320, 375, 414, 768, 1024, 1440px에서 툴바와 경로 행이 가로 스크롤을 만들지 않는다.

## 검증 범위

사용자가 과도한 테스트를 원하지 않으므로 새 위험에 직접 대응하는 테스트만 추가한다.

- 순수 함수: 밀도별 보이는 링크 수, 핵심 모드 연결성, 선택 문맥에서 숨은 링크 복원 조건
- 순수 함수: 여러 내 기술 중 강한 최대 4-hop 경로 선택, 직접 강한 연결, 경로 없음
- 컴포넌트: 기본 설정 문구, 관계·라벨 설정 변경, 시장 연결 CTA와 상태
- 회귀: 노드 선택·설정·경로 강조가 topology fetch를 보내지 않음
- 브라우저: 데스크톱과 모바일에서 설정 disclosure, 경로 강조, 노드 선택, 스크롤·터치
- 정적: 관련 Vitest, 타입 검사, 프로덕션 빌드

## 성공 기준

- 첫 화면의 그래프 면적과 기존 정보 위계가 줄어들지 않는다.
- 기본 전체 지도는 모든 관계를 표시할 때보다 선의 시각적 수가 명확히 줄어든다.
- 밀도와 라벨 설정 전후 노드 배치와 카메라는 유지된다.
- hover·선택 시 핵심 모드에서 숨은 직접 관계도 확인할 수 있다.
- 내 기술과 선택 기술 사이의 경로가 있으면 한 번의 행동으로 그래프와 텍스트 양쪽에서 확인한다.
- 사용자는 경로가 학습 순서가 아니라 공고 동시 등장 관계임을 화면에서 이해한다.
- 저사양 PC와 모바일의 기존 노드·관계 예산과 페이지 스크롤 계약을 보존한다.

## 범위 밖

- 백엔드 기술 추출·관계 점수·fit 추천 알고리즘 변경
- 선수 지식 또는 학습 난이도 데이터 생성
- 100개 이상 WebGL/worker 그래프 전환
- 옵시디언의 물리력 슬라이더, 타임랩스, 우클릭 메뉴 복제
- 홈 피드, 시장 탭, 공고 수집 기능 변경
