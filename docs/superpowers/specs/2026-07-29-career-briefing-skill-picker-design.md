# 커리어 브리핑과 기술 선택기 개선 설계

작성일: 2026-07-29
상태: Hallmark 감사 결과와 사용자의 `수정` 승인을 반영한 구현 명세
대상: 메인 화면 `/`, 커리어 화면 `/career`, 헤더의 `내 기술` 패널

## 1. 목표

메인 화면에 들어온 사용자가 시장 전체 통계보다 먼저 **지금 배울 기술 한 가지와 그 근거**를
이해하게 한다. 기술을 등록할 때는 155개의 표준 기술 목록을 훑지 않고, 검색과 키보드만으로
원하는 기술을 빠르게 추가할 수 있게 한다.

## 2. 확인한 문제

- 데스크톱 커리어 브리핑은 같은 크기의 지표 세 개가 경쟁해 다음 행동이 보이지 않는다.
- `현재 수요 상위`는 바로 옆 채용 시장 영역과 같은 값을 반복한다.
- 모바일 브리핑은 약 273px 높이로 첫 피드 항목을 아래로 밀어낸다.
- `/career`의 네이티브 `datalist`는 입력에 초점을 두면 긴 기술 목록을 브라우저 기본 UI로
  펼친다. 검색 순위, 결과 수, 모바일 높이와 시각 스타일을 제어할 수 없다.
- 헤더 `내 기술` 패널에는 별도의 검색 구현이 있어 같은 행동이 화면마다 달라질 수 있다.
- 패널의 추가한 기술은 한 줄 카드처럼 쌓여 기술이 많을수록 불필요하게 길어진다.

## 3. 검토한 방향과 선택

### 3.1 커리어 브리핑

1. 기존 3열을 유지하며 카드 높이만 줄이는 안은 지표 간 우선순위와 중복을 해결하지 못한다.
2. 브리핑을 완전히 없애는 안은 서비스의 핵심 가치인 부족 기술 분석을 홈에서 숨긴다.
3. **선택안:** 다음 학습 후보를 주 내용으로 두고, 공고 관련 수치는 보조 사실 두 개로 묶는다.
   시장 전체 수요는 기존 우측 채용 시장 영역과 피드 안 시장 카드가 담당한다.

### 3.2 기술 선택기

1. 전체 목록을 카테고리별로 접는 안은 155개를 탐색하는 부담을 그대로 남긴다.
2. 네이티브 `datalist`의 CSS만 보완하는 안은 브라우저별 목록 크기와 키보드 동작을 통제할 수
   없다.
3. **선택안:** `/career`와 헤더 패널이 공용 검색형 콤보박스를 사용한다. 빈 입력에는 목록을
   열지 않고, 입력할 때만 순위가 높은 결과를 최대 6개 표시한다.

## 4. 커리어 브리핑 정보 구조

### 4.1 기술이 등록된 상태

```text
내 커리어 브리핑                         기준 수정
전체 경력 · 전체 분야

다음에 준비할 기술
Spring                                  추천 근거 보기 →
관련 공고 55건에서 반복적으로 부족했습니다.

준비도 높은 공고 11건                   기술이 겹치는 공고 277건
필수 기술 절반 이상 충족
```

- `Spring`과 근거 링크가 첫 번째 시선과 행동을 받는다.
- 다음 기술이 없으면 `현재 반복되는 부족 기술이 없습니다.`라고 표시하고 공고 사실은 유지한다.
- `준비도 높은 공고`는 `strongFitPostingCount`, `기술이 겹치는 공고`는
  `matchingPostingCount`만 사용한다. 값의 의미를 넓혀 쓰지 않는다.
- `현재 수요 상위`는 브리핑에서 제거한다. 우측 채용 시장 영역과 피드 안 시장 카드는 그대로
  유지한다.

### 4.2 기술이 없는 상태

- 한 줄 설정 안내와 `기술 등록` 링크만 표시한다.
- 문구는 `내 기술을 등록하면 부족 기술과 준비도 높은 공고를 바로 찾을 수 있습니다.`로 쓴다.
- 시장 전체 수요를 대신 넣어 브리핑을 다시 키우지 않는다.

### 4.3 실패 상태

- `내 기술 분석을 불러오지 못했습니다.`와 `잠시 후 다시 확인해 주세요.`를 표시한다.
- 설정 링크는 유지해 사용자가 자신의 기준을 확인할 수 있게 한다.

## 5. 공용 기술 선택기

### 5.1 검색과 순위

- 입력값이 비어 있으면 결과 목록을 열지 않는다.
- 이미 추가한 기술은 결과에서 제외한다.
- 결과는 다음 순서로 정렬한 뒤 최대 6개만 표시한다.
  1. 표준 기술명 또는 별칭과 완전히 일치
  2. 기술명 또는 별칭이 입력값으로 시작
  3. 공백·점·슬래시·기호로 나눈 단어가 입력값으로 시작
  4. 기술명 또는 별칭에 입력값이 포함
- 첫 버전의 별칭은 실제로 혼동이 잦은 표기만 포함한다.
  - `js`, `자바스크립트` → `JavaScript`
  - `ts`, `타입스크립트` → `TypeScript`
  - `reactjs`, `리액트` → `React`
  - `k8s`, `쿠버네티스` → `Kubernetes`
  - `node`, `nodejs`, `노드` → `Node.js`
  - `스프링` → `Spring`
  - `postgres`, `포스트그레스` → `PostgreSQL`
  - `csharp`, `씨샵` → `C#`
  - `cpp`, `씨플플` → `C++`
- 표준 목록에 없는 입력값도 추가할 수 있다. 정확히 일치하는 표준 기술이 없으면 목록 마지막에
  `“입력값” 직접 추가`를 표시한다.
- 직접 입력은 앞뒤 공백을 제거하고, 별칭과 정확히 일치하면 표준 기술명으로 저장한다.

### 5.2 조작

- 마우스나 터치로 결과를 선택하면 즉시 추가하고 입력은 비운다.
- 입력은 추가 후에도 초점을 유지해 여러 기술을 연속으로 등록할 수 있게 한다.
- `ArrowDown`·`ArrowUp`으로 결과를 이동하고, `Enter`로 선택하며, `Escape`로 목록만 닫는다.
- 활성 결과가 없을 때 `Enter` 또는 옆의 `추가` 버튼을 누르면 현재 입력값을 추가한다.
- 결과마다 표준 기술명과 한국어 카테고리를 함께 표시한다.
- 검색 결과가 없다는 막힌 상태를 만들지 않는다. 직접 추가 행이 다음 행동을 제공한다.

### 5.3 접근성과 반응형

- 입력에는 눈에 보이는 `추가할 기술` 레이블을 둔다.
- `combobox`, `listbox`, `option`, `aria-expanded`, `aria-controls`,
  `aria-activedescendant` 계약을 지킨다.
- 입력과 버튼 높이는 44px 이상으로 맞추고 focus ring은 즉시 표시한다.
- 결과 목록은 입력 아래에 겹쳐 표시해 주변 레이아웃을 밀지 않는다.
- 결과 목록은 최대 6행 또는 사용 가능한 모바일 화면 높이까지만 보이고 내부 스크롤한다.
- 320·375·414·768px에서 가로 스크롤과 잘린 결과가 없어야 한다.

### 5.4 추가한 기술 표시

- 헤더 패널의 추가한 기술은 줄마다 카드로 쌓지 않고 줄바꿈되는 칩으로 표시한다.
- 각 칩의 제거 버튼은 기술명을 포함한 접근성 이름과 44px 터치 영역을 갖는다.
- `/career`의 기존 기술 저장, 삭제, 계정 동기화 흐름은 바꾸지 않는다.

## 6. 성능과 범위

- 검색은 이미 받은 카탈로그 배열에서 동기식으로 실행하며 네트워크 요청을 추가하지 않는다.
- 최대 155개를 정규화하고 정렬하는 계산은 입력 또는 카탈로그가 바뀔 때만 수행한다.
- 결과 DOM은 최대 7행(표준 결과 6개와 직접 추가 1개)으로 제한한다.
- 피드 혼합 비율, 자동 무한 스크롤, 페이지 커서, 공고·커뮤니티 저장 API는 변경하지 않는다.
- 새 카테고리 탐색 화면, 추천 알고리즘, 서버 스키마 변경은 이번 범위에 포함하지 않는다.

## 7. 구현 단위

- 공용 `SkillPicker` 컴포넌트와 CSS Module, 단위 테스트를 만든다.
- `/career`의 `datalist`와 헤더 패널의 개별 추천 로직을 공용 컴포넌트로 교체한다.
- `CareerBriefing`의 3열 지표를 주 추천과 보조 사실 구조로 교체한다.
- 잠긴 보라색 포인트 컬러, Pretendard, 기존 토큰과 패널 형태는 유지한다.
- `design.md`에 홈 브리핑의 역할과 검색 우선 기술 입력 규칙을 추가한다.

## 8. 검증

- Vitest: 검색 순위·6개 제한·빈 입력·직접 추가·별칭 정규화·키보드 조작·중복 제외.
- Vitest: 브리핑의 주 추천, 두 보조 사실, 미등록·실패 상태, 시장 수요 중복 제거.
- Playwright: 1440px와 390px에서 브리핑의 실제 높이와 첫 피드 위치, 두 기술 입력 화면의 목록
  높이·키보드·터치 선택, 가로 넘침을 확인한다.
- 변경된 단위 테스트와 한 개의 집중 E2E 흐름만 실행하고, 마지막에 lint와 type check를 수행한다.
