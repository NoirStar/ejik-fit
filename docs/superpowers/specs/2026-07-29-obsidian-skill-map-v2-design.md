# 옵시디언형 기술 시장 지도 V2 설계

## 목표

스킬맵을 설정 대시보드에 그래프를 붙인 화면이 아니라, 사용자가 공개 채용 시장의 기술 지형을
한눈에 이해하고 `어떤 기술을 더 배울지` 또는 `어떤 공고를 볼지` 결정하는 공간 탐색 도구로 바꾼다.

옵시디언의 장점은 노드 모양을 그대로 흉내 내는 데 있지 않다. 전체 지형이 안정적으로 유지되고,
선택한 노드의 관계만 순간적으로 강조되며, 사용자가 원할 때만 로컬 그래프로 깊게 들어갈 수 있다는
탐색 모델을 채용 데이터에 맞게 적용한다.

## 디자인 맥락

- 대상: 자신의 기술이 시장에서 어디에 놓이는지 보고 다음 학습 또는 지원 행동을 정하려는 개발자
- 핵심 행동: 전체 지형 파악 → 기술 선택 → 관계와 공고 근거 확인 → 내 기술 추가 또는 공고 탐색
- 톤: 기술적이고 조용한 `modern-minimal`
- 구조: `Map / Diagram` 안의 `시장 아틀라스 + 선택 기술 스포트라이트`
- 보존: 기존 보라색 포인트, Pretendard, 4px 간격, 44px 터치 기준, Canvas 렌더러

## 감사 결과

현재 화면의 기반 중 다음은 유지할 가치가 있다.

- Canvas 동적 로딩, 화면 비활성화 시 정지, ResizeObserver 병합 등 성능 기반
- 노드 크기·분야색·내 기술 테두리·학습 추천 점의 서로 다른 의미
- 관련 공고를 공식 원문 근거와 내부 상세로 연결하는 분석 패널
- 모바일에서 문서 스크롤을 기본으로 하고 그래프 이동·핀치를 명시적으로 켜는 방식

그러나 현재 정보 구조와 상호작용은 `Map / Diagram`이라는 선언과 맞지 않는다.

- 제목, 검색, 3개 지표, 빠른 선택, 큰 disclosure, 세 개 설정 카드가 그래프보다 먼저 나온다.
- 데스크톱 1440×1000에서도 그래프가 첫 화면 하단에서 시작하고, 모바일은 그래프가 약 487px 뒤에 나온다.
- 기본 그래프는 서버의 30개 기술·수백 관계 중 9~12개 노드와 12~18개 선만 보여 큰 그림이 없다.
- 노드를 한 번 누르면 로컬 데이터를 다시 받고 Canvas를 재구성한 뒤 2배 이상 자동 확대한다.
- 검색 입력 중에도 노드 집합이 바뀌어 배치가 흔들린다.
- 분야별 공간 구조가 없어 서로 다른 생태계가 하나의 별 모양 덩어리로 보인다.
- 그래프 아래 추천·분야 카드와 오른쪽 분석 패널이 같은 정보를 반복한다.

## 검토한 방향

### 1. 보수적 압축

현재 기능을 그대로 두고 설정 카드만 접으며 그래프 높이를 늘린다. 구현 위험은 낮지만 노드 선택 시
지형이 사라지는 문제와 로컬 그래프 중심 모델이 남으므로 옵시디언형 탐색이 되지 않는다.

### 2. 안정적인 시장 아틀라스 + 선택 스포트라이트 — 채택

전체 관계망을 기본 지도로 고정하고 선택은 1-hop 관계만 강조한다. 별도 행동으로만 선택 주변을
요청한다. 사용자는 큰 그림과 세부 근거 사이를 오가면서도 공간 기억을 유지할 수 있다.

### 3. 100개 이상 WebGL 지도

Sigma/WebGL과 worker로 매우 큰 그래프를 구성한다. 현재 API의 유효 범위가 최대 60개 기술이고
모바일·저사양 PC에서 라벨과 접근성 비용이 커서 지금 단계에는 과하다.

## 정보 구조

### 데스크톱

```text
스킬맵 · 한 문장 설명 · 데이터 범위/방법론
기술 찾기 | 전체 지도 / 선택 주변 | 내 기술 | 분야 | 읽는 법
┌────────────────────────────────────┬──────────────────┐
│ 전체 지도 · 표시 기술/관계          │ 선택 기술         │
│                                    │ 수요와 분야        │
│     분야별 느슨한 기술 군집          │ 함께 요구되는 기술 │
│     선택 시 관계만 강조             │ 관련 공고 근거     │
│                                    │ 다음 행동         │
└────────────────────────────────────┴──────────────────┘
```

- 제목 영역은 짧고, 그래프가 첫 화면의 가장 큰 면적을 차지한다.
- 내 기술, 분야, 범례는 툴바의 필요 시 열리는 패널로 이동한다.
- 오른쪽 레일은 하나의 표면 안에서 구분선으로 내용을 나누고 카드 안의 카드를 만들지 않는다.
- 그래프 아래의 `다음에 배울 기술`과 `분야 분포` 카드는 제거하고 필요한 내용은 분석 레일로 합친다.

### 모바일

```text
스킬맵 · 짧은 설명
기술 찾기
전체 지도 / 선택 주변 · 필터
┌────────────────────────┐
│       큰 그래프         │
│ 선택 기술 · 분석 보기   │
└────────────────────────┘
선택 기술 분석
```

- 그래프는 제목과 압축 툴바 바로 뒤에 오며 30rem 안팎의 실사용 높이를 확보한다.
- 기본 한 손 드래그는 페이지 스크롤, 노드 탭은 선택이다.
- `그래프 조작`을 켠 동안만 이동·핀치를 허용한다.
- 선택 후 그래프 안의 짧은 바에서 `분석 보기`를 눌러 아래 분석으로 이동할 수 있다.

## 데이터와 그래프 범위

- 최초 서버 요청은 `seed` 없이 공개 시장 그래프 최대 60개 기술을 받는다.
- URL에 선택 기술이 있고 전체 지도 60개에 없다면 그 기술의 최대 30개 로컬 그래프를 한 번 더 받아
  전체 데이터와 병합한다. 같은 기술·관계는 정규화한 ID로 중복 제거한다.
- 기본 `전체 지도`는 데스크톱 최대 48개 기술·84개 관계, 모바일 최대 30개 기술·48개 관계다.
- `선택 주변`은 최대 18개 기술·30개 관계를 보여주며 API 데이터 자체는 최대 30개를 유지한다.
- Canvas에는 선택된 보기의 제한된 데이터만 전달한다. 60개 전체 관계 수백 개를 그대로 그리지 않는다.
- 선택 기술이 기본 상위 48개 밖에 있으면 가장 낮은 우선순위 노드 하나만 교체해 포함한다.

## 상호작용 계약

### 선택

- 한 번 클릭/탭: 선택 기술과 직접 관계만 강조하고 분석 레일을 갱신한다.
- 한 번 선택으로 네트워크 요청, force 재가열, 자동 이동, 자동 확대를 실행하지 않는다.
- 이미 선택한 노드를 다시 선택하거나 모바일 `분석 보기`를 누르면 분석 레일로 이동한다.
- URL의 `seed`는 갱신해 선택 상태를 공유·복원할 수 있다.

### 전체 지도와 선택 주변

- `전체 지도`: 캐시한 시장 아틀라스를 복원하고 현재 선택을 유지한다.
- `선택 주변`: 현재 선택 기술의 직접 연결 데이터를 명시적으로 요청한다.
- `두 단계`: 선택 주변 모드에서만 활성화하고 같은 기술의 2-hop 데이터를 요청한다.
- 로컬 지도 안에서 다른 노드를 클릭해도 즉시 재요청하지 않는다. 사용자가 `선택 주변`을 다시 눌러
  새 중심 기술로 지도를 구성한다.

### 검색

- 빈 입력에서 155개 카탈로그를 펼치지 않는다.
- 입력 후 최대 6개 표준 기술을 보여주고 화살표·Enter·Escape를 지원한다.
- 타이핑은 그래프를 필터링하거나 재배치하지 않는다.
- 결과 확정 시 현재 지도에 있으면 강조하고, 없으면 해당 기술의 로컬 그래프를 불러온다.

## 공간과 시각 언어

- 분야마다 고정된 의미적 앵커를 두고 약한 X/Y force로 느슨한 군집을 만든다.
- 실제 동시 등장 link force가 앵커보다 우선해 분야를 넘는 관계를 보여준다.
- 노드 반지름은 `log1p(언급 공고 수)`를 4~12.5 범위로 매핑해 수요 차이를 읽을 수 있게 한다.
- 상위 수요, 선택, hover 노드만 우선 라벨을 표시하고 충돌 라벨은 생략한다.
- 기본 선은 얇고 낮은 농도, 선택 관계만 조금 진하게 한다. 굵은 방사형 선은 만들지 않는다.
- 채움색은 분야, 보라색 링은 내 기술, 주황색 점은 학습 추천 상위 3개라는 기존 문법을 유지한다.
- 격자 배경과 장식 그림자는 줄이고 지도 표면과 데이터가 주인공이 되게 한다.

## 분석 레일과 다음 행동

선택 전에는 다음 내용을 보여준다.

1. `기술 하나를 선택하세요` 안내
2. 내 기술이 있으면 fit API 기반 `다음 학습 후보` 최대 3개
3. 지도 시각 문법의 짧은 설명

선택 후에는 다음 순서다.

1. 기술명, 분야, 언급 공고 수
2. 필수·우대·필수/우대 미표기 수와 직접 연결 수
3. 함께 요구되는 기술 상위 6개
4. 공식 원문 기반 관련 공고 최대 6개
5. 주요 행동 `관련 공고 보기`, 보조 행동 `내 기술에 추가/제거`

## 성능과 안정성

- `force-graph` 동적 import, Canvas 2D, 자동 일시정지, resize rAF 병합을 유지한다.
- 선택·hover·내 기술 표시는 redraw만 하고 topology signature를 바꾸지 않는다.
- 전체/로컬 전환처럼 노드 집합이 실제로 바뀔 때만 simulation을 다시 시작한다.
- simulation은 1.2초 안에 식고 지속 애니메이션을 실행하지 않는다.
- 저사양 PC에서도 48개 노드·84개 선 예산을 넘지 않는다.
- 네트워크 오류 시 기존 지도를 유지하고 재시도 행동을 제공한다.

## 접근성과 반응형

- 검색 콤보박스와 함께 요구되는 기술 버튼으로 Canvas 밖에서도 기술을 선택할 수 있다.
- 모든 툴바·필터·확대 버튼은 키보드 포커스와 44px 터치 영역을 갖는다.
- 색만으로 상태를 구분하지 않고 크기, 링, 점, 텍스트를 함께 사용한다.
- 320, 375, 414, 768, 1024, 1440px에서 가로 스크롤과 하단 내비게이션 겹침이 없어야 한다.
- reduced motion에서는 공간 전환을 제거하되 선택 강조는 즉시 갱신한다.

## 검증 범위

사용자의 요청에 따라 핵심 위험에 직접 대응하는 테스트만 실행한다.

- View 단위: 전체 지도 48/84, 모바일 30/48, 로컬 18/30 예산과 선택 기술 포함
- Experience 단위: 노드 선택은 topology 요청과 모드 전환을 하지 않음
- Experience 단위: `선택 주변`과 `두 단계`만 topology 요청을 보냄
- Page 단위: 최초 전체 지도 limit 60, 희귀 seed 로컬 병합
- 브라우저: 데스크톱/모바일 스크린샷, 선택 전후 viewport 유지, 모바일 스크롤·탭·핀치
- 정적 확인: 타입 검사, 프로덕션 빌드, 관련 Vitest만 실행

## 성공 기준

- 1440×1000 첫 화면에서 그래프가 가장 큰 시각 면적이고 최소 35개 기술이 보인다.
- 모바일에서 그래프가 큰 설정 카드보다 먼저 나오고 하단 내비게이션에 가리지 않는다.
- 보이는 노드 클릭 전후 Canvas viewport와 topology 요청 수가 변하지 않는다.
- 선택 관계, 시장 수요, 분야 군집, 내 기술, 추천 기술의 뜻을 범례와 분석에서 설명할 수 있다.
- 사용자는 선택 기술에서 관련 공고 또는 내 기술 추가로 한 번에 이동한다.

## 범위 밖

- 100개 이상 WebGL/worker 그래프 엔진 전환
- 클릭 로그 기반 추천 모델 또는 임베딩 군집
- 백엔드의 기술 추출·관계 점수 계산식 변경
- 홈 피드 개인화와 커뮤니티 기능 변경
