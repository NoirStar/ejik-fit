# 홈 피드 Hallmark 감사 후속 개선 설계

작성일: 2026-07-29  
상태: Hallmark 감사 결과와 사용자의 `수정시작` 승인을 반영한 구현 명세  
대상: 메인 화면 `/`

## 1. 목표

홈에 들어온 사용자가 모바일에서도 첫 화면 안에서 실제 커뮤니티 글이나 추천 공고를 만나고,
개인화된 기술 정보가 무엇을 뜻하는지 오해 없이 이해하게 한다. 커뮤니티·공고·시장 신호를 섞는
연속 피드와 자동 무한 스크롤은 유지한다.

## 2. 확정한 방향

검토한 방향은 세 가지다.

1. 기존 순서를 유지하며 레일 높이만 줄이는 보수안은 같은 시장 수요가 계속 반복되고 태블릿 빈
   열도 남아 제외한다.
2. 모바일 전용 시장 요약 컴포넌트를 새로 만드는 안은 정보 중복과 유지보수 비용을 다시 만든다.
3. **선택안:** 데스크톱에서는 현재의 고정 시장 레일을 유지하고, 900px 이하에서는 레일을 숨긴다.
   모바일 시장 정보는 이미 무한 피드에 포함된 `MarketCard`가 담당한다.

선택안은 별도 데이터 요청이나 새 상태를 만들지 않으면서 `브리핑 → 실제 피드` 순서를 회복한다.
시장 카드는 첫 추천 공고 뒤에 이어지므로 시장 정보가 없어지지 않는다.

## 3. 화면 구조

### 3.1 데스크톱, 901px 이상

- 현재의 `커리어 브리핑 + 연속 피드 + 고정 기술 수요 레일` 구조를 유지한다.
- 레일의 `더보기`, `수집 기준 확인`은 실제 44×44px 이상의 클릭 영역을 갖는다.
- 커뮤니티 글과 시장 카드의 제목 링크도 시각적 높이는 유지하면서 최소 44px의 실제 클릭 영역을
  갖는다.

### 3.2 태블릿·모바일, 900px 이하

- DOM 순서대로 `커리어 브리핑 → 추천 피드`를 표시한다.
- 데스크톱 보조 정보인 `.rightRail`은 표시하지 않는다.
- 시장 정보는 추천 피드의 시장 카드와 상단 브리핑의 `현재 수요 상위` 한 줄로 제공한다.
- 피드 sentinel, 페이지 ledger, IntersectionObserver와 자동 다음 페이지 로드는 변경하지 않는다.
- 320·375·414·768px에서 첫 피드 카드가 초기 viewport 안에 시작해야 한다.

## 4. 정직한 지표와 한국어 문구

백엔드의 `matching_posting_count`는 전체 적합 판정이 아니라 보유 기술이 하나 이상 포함된 공고
수다. 따라서 다음 표현을 사용한다.

- `맞는 공고` → `내 기술 포함 공고`
- `필수 기술 절반 이상 N건` → `필수 기술 절반 이상 충족 N건`
- 미등록 안내 → `기술을 등록하면 내 기술이 포함된 공고와 다음에 배울 기술을 확인할 수 있습니다.`
- 실패 안내 → `내 기술이 포함된 공고를 불러오지 못했습니다.`

시장 레일의 시점은 `최근 수집 기준`처럼 모호하게 쓰지 않는다. `HomeFeedSnapshot.lastVerifiedAt`을
한국 시간으로 표시해 `공고 N개 분석 · 최신 확인 7월 28일` 형태로 제공한다. 값이 없으면
`최신 확인 시각 미상`이라고 명시한다.

## 5. 상호작용

- hover가 있는 브리핑·제목·레일 링크에는 focus와 tap/active 피드백도 제공한다.
- focus ring은 즉시 표시하고 애니메이션하지 않는다.
- 눌림 피드백은 배경색 또는 글자색 하나만 사용하며 카드 이동·확대는 추가하지 않는다.
- 주요 링크 라벨은 320px에서도 한 줄을 유지한다.

## 6. 운영 테스트 글

운영 첫 글로 확인된 `test1 / test / #test #1 #2 #3`은 UI 휴리스틱으로 숨기지 않는다. 정상적인
짧은 글까지 오탐할 수 있기 때문이다.

- 공개 API에서 정확한 post ID와 작성자를 다시 확인한다.
- 현재 스키마에는 공개/비공개 상태가 없으므로 작성자 권한 또는 운영 DB 권한 없이는 변경하지
  않는다.
- 권한을 확보하면 원본 행을 백업한 뒤 해당 글 한 건만 삭제한다. 다른 글이나 댓글은 범위에
  포함하지 않는다.

## 7. 비목표

- 추천 알고리즘, 피드 혼합 비율, 무한 스크롤 로직은 바꾸지 않는다.
- 데스크톱 레일의 데이터 항목이나 스킬 수요 계산을 바꾸지 않는다.
- 새로운 반응형 컴포넌트, 새 API, 새 디자인 토큰을 만들지 않는다.
- 내용만 보고 테스트 글을 자동 차단하는 규칙은 만들지 않는다.

## 8. 검증

- Vitest: 홈 렌더링 문구, 날짜, 반응형 CSS 계약, 터치 영역 계약.
- Playwright: 1440·768·414·375·320px 중 변경 영향이 있는 모바일 폭에서 피드 첫 항목 위치,
  레일 숨김, 가로 넘침, 무한 스크롤 유지.
- 전체 회귀 묶음 대신 변경된 홈 테스트와 한 개 홈 E2E 흐름만 실행한다.
